# Billing and reconciliation

The Cloudflare-native OpenAI **chat completions** gateway reserves the admitted request cap before the first upstream transport byte. D1 is the only monetary authority. `BillingPrincipalDO` only serializes one billable user; its local Durable Object storage is never used as balance, reservation, or ledger authority.

All monetary amounts, token counts, pricing identifiers, balance versions, and reservation versions are canonical decimal strings at JSON boundaries. The balance limit is `900719925474099100` E8 USD. D1 records an immutable reservation transition event for every operation and an immutable monetary ledger row for reserve, refund, or reconciliation. The ledger includes the signed E8 delta, before/after balance, versions, reservation version, frozen pricing version/digest, and reason/evidence digest.

Admission freezes the normalized client model, selected exact/family rule, pricing version/digest, cap, and the group's exact `rate_multiplier_bps`. Completion cannot select the multiplier. The completion wire is `2026-09-09.v2` / `gateway.usage.v2`; it carries all OpenAI usage dimensions this chat-completions gateway can prove, the effective tier, and reasoning effort. Missing usage is represented as `unknown`, retains the held reservation, and is never converted to zero. A present all-zero usage object settles as zero and refunds the whole reservation.

Settlement canonicalizes and hashes the completion payload. Exact E8 arithmetic is performed from decimal token counters and the frozen card without floating point. A calculated amount above the reservation cap is retained in the immutable usage payload while a bounded one-unit-over sentinel moves the reservation to `unknown`; it is not truncated or charged. The settlement transition and its outbox row are one D1 batch, so an outbox gap cannot follow a committed settlement. Matching replays verify the immutable billing event plus matching outbox hash; changed payloads are conflicts. Successful bridge finalization commits once, while failed/cancelled pre-start paths release once; duplicate transport delivery replays the same immutable transition.

The Worker cron also runs deterministic orphan recovery. It scans at most 25 candidates ordered by state and `created_at,request_id`, uses the row's expected reservation version and a deterministic operation ID/evidence digest, refunds an expired unstarted reservation, and moves an expired started reservation to `unknown` without refund. Every reservation carries a durable `scheduler_release_state`: billing completion remains a successful 204 once the monetary transition commits, while an interrupted RPM/lease cleanup stays `pending` and is retried without repeating the upstream call or monetary transition. Scheduler RPM/lease cleanup follows the billing transition in reverse acquisition order. Stale versions and duplicate scheduled deliveries cannot refund or charge twice; an incomplete scheduled compensation fails the invocation so Cloudflare retries it.

`POST /v1/requests/reconcile` is an internal bridge-only operation for an `unknown` reservation. It requires a stable operation ID, operator/actor ID, exact expected reservation version, `charge` or `refund` decision, an exact charge for `charge`, and a non-secret SHA-256 evidence digest. It never estimates usage. Public admin UI/auth wiring for reconciliation is deliberately not included in this batch.

Local foundation verification covers workerd/Vitest admission, billing, recovery and route wiring; strict TypeScript; generated Worker bindings; fresh/repeated local D1 migrations; and canonical Go bridge tests. It does not claim remote Cloudflare acceptance, a deployment, provisioned Durable Objects/D1/Queues/cron, or a real-upstream request. Those require a separately authorized deployment and remote readback/end-to-end run. Payment, subscription, OAuth, auth-cache, settings, and R2 acceptance remain independent lanes.
